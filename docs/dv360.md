# Display & Video 360

Official REST API version: **v4** (`src/products/dv360/api/version.ts`).

There is no official Node.js client used here. This app uses `google-auth-library` plus `fetch`.

Phase 1 is **read-only discovery**. Spend, impressions, clicks, and conversions (Bid Manager reporting) are **not implemented**.

## Credentials

Every DV360 call sends:

- `Authorization: Bearer` from the resolved Google connection

There is no developer token and no extra environment variable. The Google connection's refresh token is reused.

The authenticated Google account must also have a DV360 user role on the partner or advertiser.

## OAuth scope

`https://www.googleapis.com/auth/display-video`

This is requested together with the existing GA4 and Google Ads scopes. Existing connections created before this scope was added do **not** automatically have it.

To authorize DV360 on an existing connection:

1. Call `google_connections_start` with that `connectionId`
2. Complete Google consent again
3. The same `(operatorId, googleSubjectId)` connection is updated; a duplicate is not created

If a DV360 tool is used before that reconnect, the server returns `reauthorization_required`. It does not silently switch to another Google connection.

OAuth authorization is not the same as a DV360 user seat. A connection can show product `DV360` and still return zero partners if that Google user is not added to a partner in the DV360 UI. List tools refresh from the live API when the local discovery cache is empty.

## Discovery

On bind or reconnect, if the connection has the DV360 scope:

1. `GET /v4/partners`
2. `GET /v4/advertisers?partnerId={partnerId}` for each partner
3. Persist `dv360_partners` and `dv360_advertisers` scoped to `(operatorId, connectionId)`

Routing is always:

```text
operator + partner/advertiser
  -> product collection scoped by operatorId
  -> connectionId
  -> encrypted refresh token
  -> Display & Video 360 API v4
```

## Tools

| Tool | Source |
|------|--------|
| `dv360_list_partners` | Discovered partners |
| `dv360_list_advertisers` | Discovered advertisers; optional `partnerId` |
| `dv360_get_advertiser` | Live `advertisers.get` |
| `dv360_list_campaigns` | Live list with `pageSize` / `pageToken` |
| `dv360_list_insertion_orders` | Live list with `pageSize` / `pageToken` |
| `dv360_list_line_items` | Live list with `pageSize` / `pageToken` |
| `dv360_list_creatives` | Live list with `pageSize` / `pageToken` |

Live list tools accept official `filter`, `entityStatus`, and `orderBy` values only. Do not invent fields.

## Setup / test

1. Enable **Display & Video 360 API** (`displayvideo.googleapis.com`) on the GCP project
2. Add `https://www.googleapis.com/auth/display-video` to the OAuth consent screen
3. Keep the consent screen test users (or complete Google verification later)
4. Reconnect the Google account that has DV360 access
5. From Claude: `google_connections_list` should show `DV360` on that connection
6. Then call `dv360_list_partners` and `dv360_list_advertisers`
